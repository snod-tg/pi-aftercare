# Agent 对话与模型 API 接入

## 系统边界

```text
客户终端 → Pi Aftercare Agent → 外部模型 HTTP API
                    ↓
               售后业务工具
                    ↓
             模拟订单/库存/申请
```

模型推理服务由用户独立部署。Agent 不依赖 llama.cpp 可执行文件或模型路径，不读取 GGUF，不下载权重，也不创建推理进程。换用其他兼容的模型服务时，通过 API 配置连接；不同服务的兼容性仍需实际验证。

Pi SDK 负责向配置的接口发送消息和工具定义、解析流式响应、执行工具并把结果送入下一次请求。当前使用兼容 Chat Completions 的接口；业务 Agent 与推理服务之间只有 HTTP 请求和响应。

## 启动

模型服务需在另一个终端或独立机器上先行运行。首次使用时，在项目根目录准备配置：

```bash
cp -n .env.example .env
```

主要配置：

```dotenv
MODEL_BASE_URL=http://127.0.0.1:8080/v1
MODEL_NAME=aftercare-local
MODEL_API_KEY=local
MODEL_CONTEXT_WINDOW=8192
MODEL_MAX_OUTPUT_TOKENS=1024
AGENT_MAX_MODEL_CALLS=8
AGENT_MAX_TOOL_CALLS=24
AGENT_TIMEOUT_MS=120000
```

`MODEL_NAME` 必须与推理服务暴露的模型名/别名一致。未启用鉴权的本地服务可以使用占位值 `local`。真实密钥只放 `.env`，不提交 Git。上下文窗口是连接元数据，不能通过修改此处扩大服务实际支持的窗口。

运行交互终端：

```bash
./scripts/npm run chat
```

演示客户是 Alice，使用已有模拟订单 `O-1001`。自然语言例子：

```text
订单 O-1001，T 恤换 L 码，外套退掉。
```

程序会显示流式文本、工具名称及调用结果状态。生成方案后，程序从业务数据展示具体商品、退款金额、政策版本和有效期，并输出确认命令：

```text
/confirm Q-实际方案编号
```

此命令是终端应用处理的显式用户操作，不会作为普通聊天请求交给模型决定是否确认。程序记录确认，并生成稳定的业务操作键，再把真实记录交给 Agent 继续处理。后端和会话宿主都会检查该记录；用户在聊天中粘贴一段伪造的“确认成功”文字不能生成授权。

## 对话命令

- `/help`：显示帮助。
- `/quotes`：查看本会话当前方案。
- `/confirm <方案ID>`：确认对应方案并继续。
- `/reset`：新建对话，保留当前进程内的业务状态；新对话不继承旧对话的待确认方案。
- `/quit`：退出程序。
- Ctrl+C：请求取消当前轮次；需要退出时再输入 `/quit`。

模型 API 在 Agent 退出时继续独立运行。未配置数据库时，Agent 退出会重置内存业务数据。配置 DATABASE_URL 后，业务数据、确认和幂等记录持久化，重启可恢复待确认方案；聊天历史仍不持久化，详见 [持久化与事务](持久化与事务.md)。

命令行 `npm run chat` 与 HTTP 服务 `npm run dev` 是两个独立进程。配置同一个数据库和 schema 后共享业务数据；内存模式下各自独立。

## 限制与恢复

每条客户消息限制为 4000 字符。每轮分别限制模型请求次数、工具执行次数、最长耗时和每次输出 Token 数，达到限制后返回停止状态，不宣称任务完成。

当前保留多轮历史但未实现自动摘要；历史过长或服务返回上下文超限时，用 `/reset` 新建对话。也未提供费用预算控制：任意 API 的价格未知，程序只显示服务返回的 Token 统计，未返回的用量可能显示为 0。

模型请求失败和业务执行成功是两件事。比如售后申请已创建，但生成最终回复时模型 API 失败，终端仍从业务状态读回申请回执。重新确认同一方案时复用原确认和操作键，不创建第二份申请。取消、超时也不回滚已经完成的业务操作。

模型若重新生成同一订单的新方案，旧方案不能在此会话中继续用于提交；新方案需要重新确认。真正执行时，业务层还会检查订单、库存、政策版本和有效期。

## 验证范围

自动化集成测试注入模拟的 HTTP/SSE 响应，但使用实际 Pi SDK 解析、工具校验、执行循环及业务代码，覆盖多轮确认、伪造确认、非法工具、错误反馈、循环上限、批量工具上限、API 失败、取消、超时和写入后失败恢复。

这些测试证明调用链与约束按设计运行，不代表真实模型具备相同的规划或工具调用能力。真实模型就绪后，应再运行自然语言场景并检查工具轨迹和业务结果。

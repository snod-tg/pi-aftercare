# 评测可靠性修正

原始全量基线保留在 `.data/evals/tau-full-2026-10-19-vllm4b-c4-32k/`，75/165。修正不改写旧成绩、上游任务、业务数据或奖励函数。

## 已实现

1. **异常证据完整性。** 顾客的每次请求记录用途、尝试次数、finish_reason、正文长度、completion_tokens和total_tokens。失败响应的部分正文只存本地结果，不进入公开进度日志；失败尝试消耗的token也计入。顾客失败前的Agent回复不再丢失。Agent截断记录部分输出，且不允许截断生成的工具请求执行。
2. **Agent预算。** 当前本地配置的输出上限改为2048，顾客仍为512，上下文仍为32768。环境动作预算和模型调用预算分开配置、分别报告，计数只统计实际发起的请求。`careful-v1`默认模型预算为环境动作上限的两倍；不会提高30个环境动作的上限。
3. **Agent策略。** `careful-v1`追加通用执行规范：保留所有已表达目标、核对原商品和数量、多对象有歧义先澄清、同单完整收集、比较符合全部约束的实际数值价格、按工具事实核实资格、检查剩余任务、简洁收尾。自建售后会话也使用这些规范；宿主确认和幂等门禁保持独立执行。
4. **基于可见事实的写入门禁。** `careful-v1`只使用Agent已经查到的订单与商品返回，校验零售写入的订单状态、item归属、数量、旧新商品一一对应、同产品和可用变体。不同订单的商品不能混传，重复item ID按单位数量校验。拒绝会成为可纠正的工具观察并消耗一步。门禁不读取隐藏用户指令、参考动作或reward；不能自行推断用户的真实意图。
5. **顾客忠实性实验。** `faithful-v1`保留原用户指令与上游规则，追加禁止编造个人事实、改变目标和遗漏数量的要求。每个候选回复由一个独立模型请求审查，只看到隐藏用户指令、该顾客的对话和候选回复；没有参考答案、数据库或reward。审查不通过则限次重写，最终仍不通过就记为明确错误，不把有问题的回复送给Agent。已完成全部目标时要求单独输出`###STOP###`，拒绝无止境道别。顾客任务要求的故意主张、人格和不合作行为保留。
6. **实验隔离。** profile、输出长度、模拟器尝试次数、模型预算与新增源文件都计入manifest/代码指纹。支持重复的`--task-id retail:14`，用于定向诊断；无该参数仍运行所选完整集合。进度页会同时显示Agent与顾客profile。

## 边界

- `baseline` + `upstream`保留原策略提示和原顾客生成方式，便于对照；异常记录与截断安全处理也会应用。旧代码运行的原始基线仍以旧目录和指纹为准。
- `careful-v1` + `faithful-v1`是修改策略和模拟器的实验变体，不能声称原始官方配置复现。奖励仍由未改动的上游函数计算。
- 顾客审查仍使用同一个4B服务，属于有限的模型审查，不能保证发现所有语义错误；一般每个顾客回合增加一次审查请求，拒绝后的重试会继续增加耗时和token。每个任务内请求串行，因此四任务不会自动变成八路同时推理。
- 规范和事实校验可以减少选错对象、漏做与价格比较错误，但不能保证小模型所有决策都正确。重复商品ID不能去重；不允许因完成部分目标而自动判成功。
- 不通过读取参考答案、强制数据库匹配或随意合成STOP来提高成绩。完整目标只能由顾客自己的指令和已发生的对话判断；最终得分沿用原生协议。

## 实际回归中的兼容性修正

首轮13项诊断目录 `tau-reliability-v1-2026-10-19-c4` 发现：Qwen模板拒绝在对话末尾追加第二条system消息，导致模拟器审查后的重试返回400。该轮中止，保留调试记录，不用来报告优化成功率。

重试现在将修复要求合并进第一条system消息，保留原始任务指令。HTTP异常也记录状态和脱敏后的响应摘要。审查规则明确允许顾客不知道订单号、请求代查和逐步透露目标；不因一次未列出全部目标而拒绝，只有完成/STOP时丢目标才判为遗漏。兼容性修正后的诊断使用独立v2目录和源代码指纹。


## 当前建议：faithful-v2 + audit

第二轮v2诊断的13项完整结束，2项通过、9项执行error；其中多数error由4B审查器误判或结束标记格式处理引起。这个结果保留，不隐藏为成功实验，也不用于全量改善结论。具体发现包括审查器自己解释候选符合要求，却仍返回valid=false，或写出长篇解释耗尽审查输出预算。因此目前不建议用同一个4B的审查结论作为硬门禁。

推荐 `TAU_USER_PROFILE=faithful-v2 TAU_USER_REVIEW_MODE=audit`：

- 对邮箱、订单号、十位数字ID、常见街道地址和明确ZIP表述，程序检查它们是否已出现在原始用户指令或已接受对话里。只拦截可识别的无来源值，限次重写；有意由任务要求的虚假主张允许保留。它不是全面的实体识别，也不能证明所有自然语言事实均真实。
- 语义审查只记录诊断，不改写候选，不决定奖励，也不会把一个审查器的错误升级成任务执行失败。严格门禁仍可显式设为`enforce`做研究对照。
- `###STOP###`只在顾客原始生成中已经包含该标记时统一为单独一行。这与上游按该字面子串终止的规则一致。不会根据数据库、参考答案或“再见”推断完成，不会自行补发STOP。
- 审查理由长度限制为180字符，避免解释自身耗尽输出。重试仍只使用首条system消息。
- 自建网页Agent同步阻止截断输出中的写操作；已确认方案也不能绕过，下一轮可复用确认正常恢复。

第三轮使用v3新目录，保留所有旧实验与指纹。完整指令见上方定向回归命令。


## 最后一组工程修正

- 环境动作到达上限后，worker立即停止当前轮，不再额外请求模型。达到边界按`step_limit`记录，未进入正式终止条件仍为0分，不改为成功。
- `TAU_TRUNCATION_RETRIES`在careful-v1默认为1、baseline默认为0。仅在本trial尚未尝试任何写工具时，截断后才允许一次受模型次数和原轮次超时限制的简短重试。截断输出本身不能执行工具；一旦尝试过写操作，无论返回是否报错，都禁止这种自动重试，防止重复副作用。重试事件写入进度日志。
- `faithful-v2 + audit`默认 `TAU_USER_FACT_FALLBACK=clarify`：在连续两次生成无来源具体信息后，明确回答“不知道该信息，请换一种身份识别方法或按已知信息查询”，记录`fact_fallback`，不把编造值发送给Agent，也不生成STOP。可设为`error`保留严格中止对照。这个有限兜底不是用参考答案完成任务，也不能保证顾客接下来正确表达全部目标。
- 审查器不再决定是否接受一个来源合法的候选；审查拒绝或不可用只记录。`faithful-v2`在初始私有system消息末尾再次提示原始用户任务，降低长规则掩盖具体目标的风险。

第三轮v3仍为2/13通过，4个error（2个未知邮箱、1个2048输出截断、1个环境步数边界分类错误）。这些观察直接促成上述工程修正。第四轮使用独立v4目录；前几轮结果均保留，不能仅挑通过的轨迹展示。

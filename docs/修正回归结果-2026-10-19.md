# 首轮可靠性修正与定向回归结果

工程修正已实现并检查；本轮13个原失败任务中5个转为成功，8个仍未通过。不能声称全部问题已解决，也不能据此把全量成功率改成38.46%或推算新的全量分数。

## 修改内容

- 输出预算：当前配置Agent为2048 token，顾客仍512；上下文32K，服务与任务并发均4。
- 截断保护：不执行截断生成的工具调用。网页Agent即使已有正式确认也受保护，下一轮仍可恢复。
- 有限恢复：careful-v1仅在本trial尚未尝试任何写操作时，允许一次简短的截断恢复；写操作尝试后禁止自动重试。原超时和模型预算仍有效。
- 预算分类：环境动作到边界立即停止，正常记为step_limit；不额外请求模型后误报执行异常。模型调用与环境动作分别计数。
- 订单事实门禁：写入前检查已查询的订单状态、商品归属、数量、旧新商品配对和可用规格；不读取隐藏用户任务或参考答案。
- 目标处理规范：明确原商品规格、数量与全部已表达目标；对象有歧义先澄清，选择满足条件的最低价方案，按工具事实核实资格。
- 顾客可靠性：禁止无来源的邮箱、订单号、常见地址和十位ID；限次重写仍编造时，记录后回复“不知道该信息，请换一种识别方法”，不转发编造值，不生成结束标记。
- 审查模式：4B语义审查实测会误判，因此当前推荐audit，仅记录信号，不作为硬门禁。任务人格、逐步透露信息及有意主张保留。结束标记只规范已有的`###STOP###`，不依据参考状态合成结束。
- 诊断：保留finish_reason、输出token、有限部分输出、HTTP状态和脱敏摘要；失败尝试token计入。进度页区分定向回归和全量评测。

详细实现、实验开关与运行命令见[可靠性修正文档](评测可靠性修正-2026-10-19.md)。推理服务仍是独立HTTP服务。

### 仍未解决的8项

| 任务 | 已核查残留现象 |
|---|---|
| retail 31 | 在取消充电器、退鞋之外，多办理了一笔平板退货，最终状态偏离目标 |
| retail 93 | 顾客混淆原机32GB与目标8GB，Agent仍选择了另一订单并改成32GB替换型号；来源合法不代表意图正确 |
| retail 98 | 正确找到纽约地址，但先改商品，订单状态变化后不能再改地址；需要明确依赖顺序，而不仅是收集全部目标 |
| airline 3 | 支付方式与参考目标不同，且遗漏行李更新；曾出现礼品卡余额不足 |
| airline 6 | 修改的舱位和航班仍偏离目标 |
| airline 8 | 航班与支付组合偏离目标；使用多张证书且漏掉要求的最终金额输出，尽管工具调用成功 |
| retail 105 | 30个环境动作内未完成，正确记录为step_limit |
| airline 33 | 30个环境动作内未完成，正确记录为step_limit |

不能把这些剩余问题继续解释成接口故障。程序能阻止一部分无来源值和非法状态写入，但无法用字符串校验证明所有自然语言目标、型号选择和策略决策都正确。同一个4B审查器也没有展示出可作为语义裁判的可靠性。

下一步应保留工程保护，单独评估更强顾客模型的影响，再验证结构化目标与动作依赖的策略；保持Agent不变才能区分顾客模型改善和Agent能力改善。新策略暂作为显式实验开关，不自动覆盖baseline/upstream。尚未启动新的165项全量测评。

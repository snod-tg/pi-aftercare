# 政策检索

新增第 7 个工具 `search_aftercare_policy`，参数为 `orderId`、`query` 和可选 `limit`（1–5）。HTTP 同步提供：

```bash
curl --get 'http://127.0.0.1:3000/orders/O-1001/policy/search' \
  -H 'Authorization: Bearer demo-alice' \
  --data-urlencode 'query=退款按实付金额还是吊牌价'
```

语料位于 `data/policies/demo.json`，包含文档来源、商家、政策版本、生效/失效时间和稳定分块 ID；当前均为项目模拟政策，不代表任何真实商家的承诺。编辑后重新启动 Agent/HTTP 服务加载。文件格式和重复 ID 会在加载时校验。

检索先使用绑定客户的订单查询当前结构化政策，取得适用版本，然后按商家、版本和生效时间过滤，再执行 BM25 排序。中文按相邻双字切分，英文和编号按词切分；无额外 embedding 模型或向量数据库。返回 top-k 原文、相关度分数、`citation`、`source`、版本、有效期、SHA-256 和检索时间。它是关键词检索版本的 RAG 证据通道，不是语义向量检索，改写和生僻词的召回仍有限。

例如退款问题返回 `demo-aftercare-v1#refund`，Agent 应在解释中引用该 ID 和版本。无命中会明确返回空结果，不能随便用旧版本兜底或声称没有限制；改查 `get_aftercare_policy`，仍不明确则说明限制或转人工。结构化版本升级后必须同步发布对应检索文档，否则检索无结果，不会自动把旧文档改成新版本。

检索文档统一标记 `untrusted_reference_text`。文档里的提示词不构成系统指令，也不能签发确认、改变金额或绕过库存校验。订单归属、退款计算、确认授权和执行规则由业务服务确定。此标签和提示只辅助模型，真正的执行边界在业务校验。

验证覆盖相关条款排序、引用元数据、旧版/未来/过期/跨商家过滤、无匹配时返回空结果、订单归属和带诱导文字的政策不能改变业务金额或授权。37 项离线测试、SDK/HTTP 检查与编译通过。

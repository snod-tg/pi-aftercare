# llama.cpp 本地模型部署

## 已确认的环境

2026-10-18 本机已通过 `brew install llama.cpp` 安装推理程序。

- Homebrew 版本：`llama.cpp 0.7.0`。
- 二进制报告：build 11669，commit `620d2225c`，Darwin arm64。
- 服务命令：`/opt/homebrew/bin/llama-server`。
- 命令行推理：`/opt/homebrew/bin/llama-cli`。
- 硬件：Apple M4，24 GiB 统一内存。

已验证版本命令及启动参数帮助。模型权重尚未由本项目下载，模型服务和 Pi 的真实推理尚未验证。

## 下一步：下载并启动模型

建议先尝试 Qwen3.5 9B 的 Q4_K_M GGUF。下面命令首次运行会从 Hugging Face 下载模型，文本权重约 5.68 GB；运行时内存不等于文件大小。

```bash
llama-server \
  -hf unsloth/Qwen3.5-9B-GGUF \
  -hff Qwen3.5-9B-Q4_K_M.gguf \
  --alias aftercare-local \
  --ctx-size 8192 \
  --gpu-layers all \
  --jinja \
  --host 127.0.0.1 \
  --port 8080
```

这是待运行的启动命令，不是已完成的部署记录。初期使用 8K 上下文和单个测试会话，后续根据实际内存与速度调整。下载的模型缓存和二进制不应放入项目 Git。

服务就绪后，在另一终端检查：

```bash
curl --fail http://127.0.0.1:8080/health
curl --fail http://127.0.0.1:8080/v1/models
```

Pi 将使用 `http://127.0.0.1:8080/v1`，模型别名为 `aftercare-local`。项目自身的业务服务仍使用 3000 端口。接入时还需要配置模型运行时、显式选择该模型并提供聊天入口；当前 SDK 离线测试不会连接本地服务。

先验证普通对话，再验证模型能返回实际的结构化工具调用；能生成聊天文本不等于已验证工具调用。模型服务加载失败或工具调用不兼容时，应根据服务日志和实际 API 返回排查。

来源：[Unsloth 权重文件](https://huggingface.co/unsloth/Qwen3.5-9B-GGUF/blob/main/Qwen3.5-9B-Q4_K_M.gguf)、[llama.cpp 服务文档](https://github.com/ggml-org/llama.cpp/tree/master/tools/server)。参数以本机 0.7.0 的 `llama-server --help` 为准。

# 独立模型服务记录

## 部署边界

模型推理服务由用户独立部署和维护。Pi Aftercare 只通过模型 HTTP API 调用它；项目不提供模型下载、GGUF 加载、推理引擎安装或服务进程管理功能。

2026-10-18 已检查本机通过 Homebrew 安装的 llama.cpp 0.7.0（build 11669，commit 620d2225c），其 `llama-server` 可执行。用户另行下载并管理模型文件；文件路径不是 Agent 配置项，也不是模型 API 的模型名。

这份记录不表示模型服务已经就绪或真实推理已经验证。

## Agent 需要的连接信息

| 配置 | 当前约定示例 |
|---|---|
| API Base URL | `http://127.0.0.1:8080/v1` |
| Model | `aftercare-local`，须匹配服务暴露的别名 |
| API Key | 本地未启用鉴权时使用占位值 `local` |
| API 协议 | 兼容 Chat Completions，支持流式输出与工具调用 |

推理服务和业务服务使用不同端口，示例分别为 8080 和 3000。切换推理后端时修改连接配置并验证协议兼容性，不需要在 Agent 中引入该引擎。

服务就绪可由用户在独立终端检查：

```bash
curl --fail http://127.0.0.1:8080/health
curl --fail http://127.0.0.1:8080/v1/models
```

随后按 [Agent 对话与 API 接入](Agent对话与API接入.md) 配置并启动客户端。健康接口和模型列表可用不等于工具调用已通过验证，还需用实际业务场景联调。

# 售后网页

网页使用 React + Vite，业务 HTTP 服务保留 Fastify，Pi SDK 继续运行在 TypeScript 后端。FastAPI 是 Python 后端框架；当前阶段保留一个业务服务，避免为了网页引入第二套服务和跨语言会话通信。模型仍是独立部署的外部 HTTP API。

## 启动

在项目根目录，确认 `.env` 中的 `MODEL_BASE_URL`、`MODEL_NAME` 已配置；数据库按现有 `DATABASE_URL` 配置使用。模型与 PostgreSQL 需要独立运行。

```bash
# 编译前后端，然后启动；浏览器打开 http://127.0.0.1:3000
./scripts/npm run build
./scripts/npm start
```

修改页面时，在两个终端分别运行：

```bash
# 终端一：业务服务，默认 127.0.0.1:3000
./scripts/npm run dev
```

```bash
# 终端二：网页热更新，浏览器打开 http://127.0.0.1:5173
./scripts/npm run dev:web
```

开发页面通过 Vite 将 `/api` 请求代理到 3000；正式构建由 Fastify 同源提供 `web-dist/` 静态文件。修改页面后，正式服务需要重新构建；修改后端后还需要重启业务服务。不要把模型密钥放入 `VITE_*` 变量。

## 使用闭环

1. 默认演示顾客 Alice，订单 `O-1001`。输入“T 恤换 L 码，外套退掉”，或点击快捷需求。
2. 助手通过真实业务工具查询政策、库存并生成方案；右侧列出实际检索条款、版本、检索时间和工具执行记录。
3. 方案卡片展示后台计算的商品、退款金额和有效期。点击“确认并提交”才记录正式确认；普通聊天中的同意不能代替该操作。
4. 后端保存确认凭据、稳定的幂等键，随后让同一个 Agent 会话继续处理。浏览器不提供或决定这些凭据。
5. 回执来自业务状态读取。创建成功显示“等待寄回、退款尚未开始”；这是模拟商家，不处理真实资金或物流。

“停止”取消后续模型处理，已经提交的业务操作不回滚。页面优先根据实际申请回执判断是否创建成功。失败后可继续说明需求或要求查询申请状态；过期方案需重新生成并确认。

## 接口与边界

- `GET /api/meta`：配置是否存在、模型名、存储类型；不返回 API Key 或数据库连接信息，也不把“已配置”当成模型健康。
- `POST /api/sessions`：创建会话；`GET /api/sessions/:id`：恢复当前快照。
- `POST /api/sessions/:id/messages`：`{content}`，SSE 返回 `start`、`trace`、`result` 或 `error`。
- `POST /api/sessions/:id/confirm`：`{quoteId}`，SSE 继续处理；禁止额外提交身份或确认凭据。
- `POST /api/sessions/:id/cancel`：停止本轮；`DELETE /api/sessions/:id`：关闭空闲会话。

网页目前固定使用公开的 `demo-alice` 演示令牌；接口绑定对应顾客身份，跨用户会话访问返回 404。它不是生产身份验证方案，仅供本机项目演示。

对话历史保存在单个业务服务进程中，浏览器只保存会话 ID；同一进程内刷新页面能恢复，运行中的轮次会轮询状态。空闲会话 45 分钟后清理，最多保留 32 个；新对话不会自动导入旧对话。业务服务重启后需新建对话；已持久化的业务申请仍留在 PostgreSQL 中。尚未实现跨进程的聊天历史、申请列表或顾客登录。

## 验证

```bash
./scripts/npm run check
# 需要已运行的本地 PostgreSQL；测试使用隔离 schema
./scripts/npm run test:postgres
```

新增 `tests/web.test.ts` 使用实际 Pi SDK 循环和业务工具，只替换模型 HTTP 响应，验证 SSE、政策依据、按钮确认、拒绝伪造凭据、重复提交、身份隔离、并发拦截、取消与继续。

网页浏览器联调在独立测试端口使用相同后端代码和模拟模型响应，验证了聊天到方案、展开政策、点击确认、实际回执及订单申请数量更新。正式页面配置连接现有外部模型 API；本次未额外调用正在进行全量评测的真实模型，真实模型的决策质量依旧取决于模型自身。

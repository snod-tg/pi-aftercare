# 双4B独立API评测

2026-10-19，用户要求Agent和用户模拟器各使用一个独立4B进程。此前两种角色的提示词、消息历史和会话对象已分离，但共用9B推理API；不能将此前失败归因于历史串线。

当前独立服务均使用 Qwen3.5-4B-Q5_K_M，关闭思考，上下文32768：

| 角色 | Base URL | 模型别名 |
| --- | --- | --- |
| Agent | http://127.0.0.1:8080/v1 | aftercare-agent-4b |
| 用户模拟器 | http://127.0.0.1:8081/v1 | aftercare-user-4b |

`.env` 对应 MODEL_BASE_URL/MODEL_NAME 和 TAU_USER_BASE_URL/TAU_USER_MODEL，密钥分别使用 MODEL_API_KEY、TAU_USER_API_KEY。本机服务未启用鉴权时可用local占位；真实密钥不提交。推理进程由用户独立管理，Agent只访问API。

两个服务有独立进程、模型上下文和请求队列，仍共用同一台Mac的GPU和内存。两边使用相同权重，拆服务不会自动提高模型能力，4B也不保证比9B更会模拟用户；本轮同时改变了模型大小和部署方式，结果差异不能只归因于其中一个因素。

先重测此前完成的官方retail test第0、1、2项，保持原始任务、规则、用户模拟器提示、评分和30步上限：

```bash
./scripts/npm run tau:full -- --domain retail --split test \
  --task-start 0 --task-stop 3 --trials 1 \
  --output .data/evals/tau-pilot-2026-10-19-dual4b-32k
```

